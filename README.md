# 水族店多缸水质值班台

晚班交接前用的多缸水质值班台：登记读数、生成待处理项、排换水队列、交班责任转移，数据存在浏览器本地，关闭再打开仍接得上。

## 技术栈

React 19 + Vite + TypeScript + 原生 CSS（无 UI 框架，localStorage 持久化）

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5105

## 业务规则

### 读数与待处理项

- 登记各缸 **水温、pH、氨氮、硝酸盐**，品种上限随鱼的品种而定（淡水观赏鱼 / 草缸灯鱼 / 三湖慈鲷 / 海水鱼）。
- 任一指标超过该缸品种上限：
  - 该缸该指标**没有未关闭的待处理项** → 新建待处理项；氨氮/硝酸盐同时自动生成换水任务进待排队列。
  - 已经有未关闭的待处理项 → **只补一条检查记录**，不重复建项（首测值、补测次数与复测值都挂在卡片上）。
  - 读数回到上限以内 → 标记「复测达标」，人工确认后才关闭。
- 氨氮超限为**紧急**；硝酸盐按超限幅度分为紧急 / 优先；水温、pH 超限为常规处理（不靠换水）。

### 换水排期

- 当晚时段固定：20:00–22:30，每半小时一个时段。
- 「一键按紧急程度排期」按 紧急 > 优先 > 常规处理 > 计划换水 排序，同级先登记先排。
- **一个鱼缸一晚只占一个时段**：同缸的其它换水项停在「待排」，卡片内说明冲突原因；时段被占或排满时手动选时段会被拒绝并提示。
- 可手动选时段、撤回待排、标记完成、移出计划换水；还能登记不依赖异常项的周换水。

### 筛选与交班

- 顶部鱼缸卡片可按缸筛选；视图分「待处理 / 换水 / 已完成 / 全部动态」。
- 「交班给下一班」后，未关闭待处理项与未完成换水任务的责任全部转到下一班（卡片显示现归属班次），已完成项保留完成班次。
- 全部状态（鱼缸、班次、读数、待处理项、任务、交班记录）写入 `localStorage`，重开页面自动恢复；「重置演示」可回到内置演示数据。

## 目录

- `src/types.ts` — 数据模型
- `src/model.ts` — 业务规则（读数处理、紧急程度、排期、交班）
- `src/seed.ts` — 演示数据（早班已完成一项、晚班四组演示读数）
- `src/store.ts` — localStorage 持久化与提示
- `src/components/` — 值班台各面板
